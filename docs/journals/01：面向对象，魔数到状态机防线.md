## 一、面向对象的本质与编译原理透镜

### Q1: C++ 所谓的面向对象只是语法优化（语法糖）吗，还是为了解决更深层次的问题？

> **我的发问**：
> “我现在搞明白了 cpp 所谓的面向对象是什么了，这只是一个语法的优化吗，还是为了解决一些更深层次的问题？所以指针解决了一件事情：传参传的是形参无法修改实参。”

* **解惑与启发**：
  * **在机器码层面，面向对象 100% 只是语法糖**：CPU 和汇编里根本没有“类”的概念，底层依然是把结构体首地址放入寄存器，然后去 `CALL` 目标函数的内存地址；
  * **但在工程维度，它解决了系统防崩溃的生死问题**：把“数据”与“能对数据做的动作”死死绑在一起，杜绝把修自行车的函数误传给汽车数据，同时通过 `private` 锁死敏感字段，立起防御边界。

### Q2: Python 的 `self` 在调用时怎么知道具体要指定的对象是谁？

> **我的发问**：
> “python 这个 `self` 怎么知道我具体要指定的对象是谁？”

* **解惑与启发**：
  * 关键就在于调用时的**那个小圆点 `.`**；
  * 当你写 `dog1.bark()` 时，Python 解释器在底层自动把它改写成 `Dog.bark(dog1)`——**写在圆点前面的对象，在运行时被解释器自动作为第一个实参喂给了形参 `self`**。

---

### Q3: Go 语言把指针/对象放在前面，到底做了什么？

> **我的发问**：
> “所以 Go 这个语法做了一件事：把指针（或者说对象）放在前面。”

* **解惑与启发**：
  * 一针见血。Go 语言不搞类的伪装，直接把指针作为**接收者 (Receiver)** 端正放在函数名最前面：
    `func (m *MatchState) ValidateInvariants() error`
  * 既解决了纯 C 语言函数无法同名复用的笨重，又省去了 C++ 复杂的继承体系，大道至简。

### Q4: 内存到底长什么样？printf 是怎么输出的？

> **我的发问**：
> “**`printf("%d", r1.hp);` 所以这一行代码就是把 `r1.hp` 对应的内存翻译成十进制输出？**”

* **解惑与启发（透镜理论）**：
  * **分毫不差。** 内存物理上只有纯粹的二进制电荷状态（如 `01011010`）。
  * `"%d"` 并不是变量自身的属性，而是人类观察内存的一副**“翻译透镜”**：
    * 戴上 `"%d"` 透镜看：翻译为十进制数字 `90`；
    * 戴上 `"%x"` 透镜看：翻译为十六进制 `5a`；
    * 戴上 `"%c"` 透镜看：翻译为 ASCII 大写字母 `'Z'`。
  * **内存里的二进制分毫未变，改变的只是人类观察它的透镜。**

## 二、状态机防线、魔数与系统可维护性

### 业务背景代码 (server/models/state.go)

为了让讨论不悬空，此处截取我们编写的比赛状态机核心片段：
```go
// 比赛状态枚举：穿上强类型安全马甲
type MatchStatus string

const (
    MatchStatusReady     MatchStatus = "ready"     // 未开始
    MatchStatusOngoing   MatchStatus = "ongoing"   // 进行中
    MatchStatusCompleted MatchStatus = "completed" // 已完赛（终态）
)

// 状态机单向流转守恒检查
func (m *MatchState) CanTransitionTo(nextStatus MatchStatus) bool {
    // 完赛记录不可倒灌修改
    if m.Status == MatchStatusCompleted && nextStatus != MatchStatusCompleted {
        return false
    }
    return true
}
```

### Q5: 为什么不用数字（0, 1, -1）或者 bool，非要写长字符串？

> **我的发问**：
> “这个自定义类型有点类似于一个 if-else 判断吧，符合条件的字符串才可以传进来。这里追问一句，他的作用映射到比赛中是什么？如果只是为了表示比赛进行情况**不能用 bool 值或者其他符号代表（0，-1，1）来表示吗？为什么要用字符串来写？**”

* **解惑与启发**：
  * `bool` 只有真假两态，装不下准备、进行、暂停、完赛、弃赛等多状态；
  * 裸数字 `0, 1, -1` 是软件工程中臭名昭著的**“魔数（Magic Number）”**：过了几年再读代码，谁也记不得 2 代表什么，前后端联调查 bug 查到吐血；
  * 语义化字符串（`"ongoing"`, `"completed"`）具备自解释性，几年后翻看数据库或抓包依然一眼看懂，**保证了系统的长期可维护性**；配合 Go 的 `type MatchStatus string`，同时享有编译期防呆安全。

### Q6: `CanTransitionTo` 在代码层面具体是怎么把幽灵请求击毙的？

> **我的发问**：
> “**你再细讲一下 `CanTransitionTo` 具体是怎么实现你说的功能的。**”

* **解惑与启发**：
  * 后端收到状态更新请求时，先取数据库现存状态 `m`（`completed`），再看网络新送来的状态 `nextStatus`（`ongoing`）；
  * 核心门禁判定：已完赛状态只要遇到非完赛的新状态，函数直接返回 `false`；
  * 接口当场阻断并返回 HTTP 400 报错，**拒绝触碰数据库**，直接将弱网卡顿导致的旧幽灵请求击毙在内存门外。
